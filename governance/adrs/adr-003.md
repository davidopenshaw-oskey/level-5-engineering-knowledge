# Knowledge Pipeline Design Journal — ADR 003

## Title
**"Don't Throw It All at the LLM" Is Not a P1-Specific Fix — It Recurs at Every Synthesis Layer**

## Status
**Approved & Implemented (principle); mitigation tactics not yet implemented**

## Date
2026-08-01

---

# 1. Context

ADR-000 established the founding insight of this whole pipeline: an LLM asked to read raw, unbounded source code directly and synthesize understanding from it produces unreliable, unrepeatable results ("prompt dependent... interpretation mixed with extraction... limited traceability"). Phase 1 exists specifically to fix this — extract deterministic, bounded facts first, and only hand knowledge-synthesis work a corpus of those facts, never raw source.

On 2026-08-01, during the first live test of Phase 2's automated module-profile generator against a real module (`building`), the same category of failure reappeared — not because raw source leaked into the prompt, but because the *entire raw evidence graph* for `building` (2,498 structured facts) was fed to the LLM in a single, unbounded pass. Measured, not guessed:

- The full assembled prompt was 1,376,733 tokens — exceeding Gemini's 1,048,576-token context window outright (HTTP 400, confirmed via a real failed API call).
- `building`'s evidence graph alone, as stored, is ~4.19MB (~1,047,000 tokens) — almost exactly one entire context window, by itself, before grounding docs or instructions are added.
- Breaking the graph down by fact type showed `call_expression` facts alone account for ~64% of that size (2.2MB of 3.43MB of compact-JSON facts), and that nearly every fact is stored twice (flattened top-level fields duplicated again inside a nested `evidence` blob) — a de-duplication + reformatting pass (dropping the duplicate, converting high-volume uniform-schema fact arrays to CSV/table form) brought the same graph down to ~1.34MB (~352,000 tokens), fitting comfortably within budget alongside grounding docs.

---

# 2. Decision

The requirement Phase 1 was built to satisfy — **never hand an LLM an unbounded corpus in a single pass and expect reliable, repeatable results** — is not a one-time fix that Phase 1 discharges on behalf of every later phase. It is a standing constraint that reapplies at *every* layer of this pipeline: raw source → facts (Phase 1's job), facts → module knowledge (where this broke today), module knowledge → repo knowledge, and repo knowledge → cross-repo knowledge (Phases yet to be built).

The failure mode is about the **boundedness of a single LLM call**, not about whether the content being fed to it is "raw source" versus "structured facts." Structured facts are more information-dense per token than prose, which raises the volume of material needed to trigger the same failure — it does not eliminate the failure mode, and today's evidence shows the threshold is reached sooner than expected: at the single-module level, on the first real module tested, not several pipeline layers up as originally assumed.

Therefore: **every future Phase 2+ synthesis stage must be designed from the outset assuming it needs deliberate staging/bounding of its own input** — de-duplication, pre-aggregation, compact reformatting, map-reduce fan-out, and/or retrieval, as fits the specific stage — never assumed to "just fit" because the input happens to already be structured facts rather than raw text.

---

# 3. Relationship to ADR-002 (Facts Stay Raw)

This does not contradict ADR-002's decision that extraction stays strictly fact-based and unformatted. ADR-002 governs the **canonical, stored** evidence graph — that stays exactly as extracted, untouched, for every consumer. This ADR concerns a **separate, ephemeral transformation** that may need to exist *between* that canonical storage and any single LLM prompt that consumes a slice of it — a prompt-assembly-time projection (de-duplicated, filtered, reformatted), not a change to the stored fact layer itself. The canonical facts remain raw; what's new is recognizing that a bounded, LLM-facing *view* of them is a legitimate and likely necessary additional artifact, not a violation of keeping facts raw at the source.

---

# 4. Consequences

- Every new Phase 2+ synthesis stage's design should explicitly answer "how is input to this LLM call bounded, and by what mechanism" *before* it is built — not discover the answer by hitting a context-window error during testing, as happened here.
- This revises an assumption baked into the original 5-level synthesis hierarchy (ADR-001): that boundedness would emerge naturally at higher layers simply because each layer reads the *output* of the layer below (a profile) rather than raw facts. Today's finding shows that assumption must be explicitly verified at *every* layer, including the first one (module-level) — it does not hold automatically just because an input is smaller or more structured than the layer beneath it.
- This ADR fixes the *principle*, not the *tactic*. The specific mitigation techniques for the `building` case (de-duplication, feeding pre-resolved call edges instead of raw call facts, pre-aggregating high-volume fact types, CSV/table reformatting, map-reduce within a module, retrieval-on-demand) are catalogued and measured in `governance/roadmap/tasks.md`'s checkpoint entries, and remain undecided/unimplemented as of this ADR — this document exists so the *principle* they're all instances of isn't lost or rediscovered independently at the next layer (repo-level synthesis) the hard way.
