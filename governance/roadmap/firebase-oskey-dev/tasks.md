16. `contracts/00-capability-synthesis.md`'s "Citing evidence inline" section currently presents fact-ID and file-line citations as equally valid, with fact-ID only "preferred when the claim comes from one specific fact" — but they're not equally robust. File-line citations (`` `path.ts` (lines N-M) ``) are pinned to a specific commit's line numbers and go stale from ANY source change that shifts lines above that point in the same file — even a single comment added, no semantic change at all. Fact-ID citations don't have this problem: `stableFactId()` already excludes line number from identity (fixed earlier, Plan 03 Stage 1), so a fact-ID citation survives a comment addition untouched. Strengthen the contract to explicitly prefer fact-ID citations for this reason (not just as a vague preference), reserving file-line citations for cases with no single backing fact (e.g. a multi-fact code range). Separately worth noting as a mitigation already available without a contract change: re-running `validateCitations()` against freshly re-extracted Phase 1 facts (cheap, no LLM) against an *existing* document's text will correctly flag drifted file-line citations as "line-unverified" — a free staleness detector, not a reason a full re-synthesis is required after every source edit.
