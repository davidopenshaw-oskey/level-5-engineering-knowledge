3. ~~Generalize the prototype loader into a real TypeScript sync script.~~ **Done 2026-09-02.** `pipeline/facts-postgres-index/sync-facts.ts`, `REPO_NAME`/`MODULE_NAME` env-driven matching this pipeline's existing convention, reuses `runContextPath` from Phase 1's shared utils (read-only).    Three real, distinct bugs found and fixed by actually running this against real data, not just reading the code:
   - **Fixed a real bug the Python prototype had**, not a new risk introduced here: it only ever read `_module_root.json`, silently missing every other capability pack in a multi-capability module. Verified against `supplier` (`_module_root.json` + `supplierStaff.json`, 784 facts combined) — confirmed real `supplierStaff`-specific facts (e.g. `createSupplierStaffAccess`) are now present, which the old prototype would have missed entirely.
   - **A real Postgres type error on the first live run**: `column "line" is of type integer but expression is of type text` — parameterized multi-row `VALUES` arrive untyped over the wire; fixed with explicit `::text`/`::integer`/`::jsonb` casts per column.
   - **A real logic bug in the reporting counts**: the first version counted `was_insert` and `embedding_missing` as mutually exclusive, so 784 brand-new facts (for `supplier`) reported as "0 need embedding" — impossible, since a new fact obviously has no embedding yet. Caught by actually reading the printed output against what it should say, not by inspecting the code alone. Fixed: the two are independent facts about a row, not alternatives.

   Verified after fixes: idempotent re-runs (0 new, correct needs-embedding count, 0 pruned on a repeat sync of both `tasks` and `supplier`), and prune logic confirmed with a real injected stale row (inserted manually, synced, correctly reported "1 stale facts removed," confirmed gone).
