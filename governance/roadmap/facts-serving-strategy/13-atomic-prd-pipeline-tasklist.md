   **Two real bugs found by reading the actual generated output, fixed and reverified:**
   - `assemble-prd.ts`'s substitution was context-blind — the template's own header comment illustrates each placeholder using the same literal `{{name}}` tokens the real body uses, and a global replace mangled the comment along with the real insertion points. Both fixes verified by re-running and re-reading the real output; typechecks clean.

   **Real, standalone finding, not yet resolved — the retrieval result itself was confidently wrong.** `search()` returned `confident: true` (top distance under the 0.76 threshold) and 10 results, but every one was `_deleteAccessSideEffects`/`deleteNonAppUserAccess` — a different actor's removal code path (`nonAppUser`, an actor type not discussed anywhere in this project so far) — not `removeInhabitantFromUnit` (the real function `08` is built on) or `OSKTaskSchedulerService.scheduleTask`/`cancelTask` (the scheduling mechanism, `08`'s key finding). Per explicit 2026-09-03 direction, this is recorded as a real, standalone finding rather than chased with more tuning against a single query right now — see `05-tasklist.md` for where this should be picked up (a new item, not yet added, when this is prioritized).
