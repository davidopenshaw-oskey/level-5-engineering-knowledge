## Facts about this environment you must not get wrong

- **DB:** container `facts-postgres-index-local` (port 5433), database `facts_index`, user `facts_index`. It is live and shared; there is no copy. Use `</dev/null` with `docker exec ... psql -c`, or it can hang.
- **One extractor binary serves all 5 Swift repos** (ios-oskey-dev, swift-cloud-kit-oskey-dev, swift-ui-kit-oskey-dev, swift-ble-kit-oskey-dev, swift-webrtc-kit-oskey-io). Rebuild with `swift build -c release` in `swift-extractor/`. Any change can alter all five, so **the gate covers all five**.
- **`fact_ref` = `sha1(fact_id)`, generated by Postgres** on `facts` and on both ends of `cross_repo_edges`. A Swift call fact's `fact_id` is built from `calleeExpression`, `callerFunction` and `callerClass`. **Never change what feeds `stableFactId()`.** In particular, never fill in `callerFunction` where it is empty today (only 5,640 of 17,442 iOS calls have it): the new caller information goes in the new `callerMember` field (spec §2a). Your gate reports `fact_id` **and** `fact_ref` diffs per repo; the expected answer is 0 changed, 0 pruned.
- **Upstream:** the kits are pinned by commit. `ios-oskey-dev` tracks `master` (`e660bda2` on 2026-10-01). `00-scan-repo` re-clones, so run `git ls-remote https://github.com/oskey-io/ios-oskey-dev.git refs/heads/master` first; if it moved, **stop and tell the user**.
- Existing payload fields are **never renamed or re-meant**, only added to.
- **CLAUDE.md rules that bind you:** always dynamic (walk real syntax; no hand-typed lists of types, properties or methods); cheap bounded tests first; keep a before baseline and compare; write findings as they happen; delete scratch scripts afterwards; **no LLM calls; no `gcloud`; any embedding spend is flagged with a count and token estimate (~143 tokens/fact for Swift) and waits for the user.**

## Procedure

**S1, investigate and confirm the contract (read-only).**
- Check spec §2a-2c against the real code and data: the overload handling, how extension members carry `parentType`, how property initializers look across the 5 repos (measure the shapes, don't assume), how many iOS calls each resolution tier (§2c, 1-3) would newly resolve (estimates are fine, labelled as such), and the open constructor-call question in §2a.
- Measure the A1/A2 call sites and their targets in the live facts, and record the **before** numbers (resolution counts per `resolutionMethod` per repo; the A4 edge counts from the spec).
- Post `[Lane S] S1 CONTRACT CONFIRMED / AMENDMENTS` in the Build log, with every amendment and its reason, and **stop for approval**.

**S2, build and bounded test.**
- Implement in `main.swift` (property `declaredType`/`declaredTypeSource`, `calleeMember`, `callerMember`/`callerMemberKind`) and in step 01 (the (type, member) index, resolution order §2c, the new fields).
- Bounded test first: extract **swift-cloud-kit-oskey-dev** and **ios-oskey-dev** into held runs (files only). Show A1 and A2 resolved with the exact fields, the before/after counts per resolution tier, and 5 random newly-resolved calls checked against source in `output/clones/`. Also show 5 that stay unresolved, with their reasons.

**S3, extract all 5 and gate.**
- Extract all 5 repos (held runs, files only). Run the pre-sync gate per repo and module: `fact_id` and `fact_ref` identical / new / would-be-pruned, plus the number of facts whose **description** would change under the current `sync-facts.ts` (that's the embedding count). Lane E owns `descriptionFor`; if Lane E has changed it, use the shared file as it is.
- Post `[Lane S] READY TO SYNC` with the gate numbers per repo, the embedding estimate, and anything unexpected, then **stop**. The user takes it to the coordinator.

**Write turn (only after `WRITE TURN GRANTED: Lane S`).** Dump (`output/backups/facts_index-<date>-before-laneS.dump`); `sync-facts.ts` per (repo, module) with `EMBED` unset; report the counts; flag embedding and wait for the user's go; `EMBED=true` only after it; then `build-edges.ts --dry-run` (read-only) to confirm 0 dangling and no unexplained STALE. **Do not run `pipeline:edges`** (spec §3: W6 would pick up the new Swift facts before Lane E's numbers are reviewed). Post the numbers, then `WRITE TURN RELEASED: Lane S` requested, and stop.
