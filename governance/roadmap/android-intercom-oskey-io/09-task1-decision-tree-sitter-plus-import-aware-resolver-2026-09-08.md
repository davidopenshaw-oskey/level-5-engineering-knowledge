# Task 1 — Decision: tree-sitter-kotlin + a Custom Import-Aware Symbol Table

**Status: DECIDED, 2026-09-08.** Supersedes `05-task1-scip-kotlin-disqualified-2026-09-08.md`'s "front-runner" framing (itself already superseded once by real setup-cost findings — see `08-...md`). This is the real, final Task 1 decision, grounded in a bounded, real parse test against this repo's actual code (`08-task1-consolidated-checklist-2026-09-08.md`), not research alone.

## The decision

1. **Extraction tool: `tree-sitter-kotlin`** (the `fwcd/tree-sitter-kotlin` grammar, via the `tree-sitter-kotlin` npm package) for all declaration-level facts — classes, functions, properties, `enum class` members, `sealed class`/`sealed interface` hierarchies, generic type-argument descent, Compose `@Composable`/annotation sites.
2. **Call-graph / cross-module / RBAC resolution: a custom, lightweight, import-aware symbol table**, built on top of tree-sitter's per-file parses — not `kotlin-compiler-embeddable`, not a bare heuristic. Concretely: walk every file's `package` declaration, `import` statements, and top-level declaration names across all 5 modules; resolve each call site by checking that specific file's own real imports first, falling back to same-package resolution when nothing was imported for that name.
3. **`kotlin-compiler-embeddable:1.8.10`** (`market-research/19-...md`) is not used for the initial build. Recorded as the fallback if the import-aware resolver's real accuracy, once built, turns out worse than this bounded test predicted.

## Why, grounded in real, measured results (not research alone)

**Declaration-level extraction is safe with a syntax-only tool.** Re-reading the actual TS pipeline code (`06-ts-pipeline-lessons-reflagged-for-tree-sitter-2026-09-08.md`) found that most of what looked like it needed real compiler resolution — generic type-argument descent, closed-set enum/union values — was already pure syntax-tree walking in the proven `ts-morph`-based code. A bounded real parse test against this repo confirmed the Kotlin analog holds: **130 of 136 real `.kt` files (95.6%) parsed with zero errors**, including every real closed-set-value and generic-wrapper case tested (`OSKAccesses.kt`'s constructor-bearing enums, `OSKIntercomScreens.kt`'s 11-subclass sealed hierarchy, the `NavHost`/`composable` trailing-lambda file) — well above the grammar's own generic, self-reported 61.2% structural-match number, because that number reflects a broader, more adversarial cross-validation corpus than this specific codebase's actual style.

**The 4.4% of files with real parse errors are a bounded, localized risk, not a blocking one.** Root-caused directly: the dominant cause (4 of 6 affected files) is one specific, genuinely new tree-sitter-kotlin bug — assignment through a call-then-navigation chain (`obj.method(args).property = value` fails; reading the same chain, or assigning without a call in the chain, both parse fine) — manifesting from one real line of code copy-pasted across those 4 files. Checked the blast radius directly in the worst-affected file: all 19 real function declarations and 99 real property declarations elsewhere in that same 771-line file still parsed correctly, including declarations both before and after the error region. Not a corrupted file — a handful of unparseable statements within an otherwise-usable file.

**Real, compiler-exact call-graph resolution isn't available to any syntax-only tool** (`07-call-graph-resolution-gap-major-finding-2026-09-08.md`) — but the real severity of that gap depends on how often name-based resolution is actually ambiguous on this specific codebase, which is an empirical question, not a theoretical one. Tested it directly: a repo-wide scan of all 5 modules' top-level declarations found only 4 duplicated names total, 2 of which (`ExampleUnitTest`, `ExampleInstrumentedTest`) are Android Gradle test scaffolding, never called cross-module, irrelevant. The 2 real, substantive collisions (`OSKAnalyticsService`: 3 declarations; `OSKConfigurationData`: 2 declarations) were checked against a real call site, and Kotlin's requirement for an explicit, unambiguous `import` per cross-package reference (no barrel/re-export indirection the way TypeScript has) resolved the ambiguity cleanly — the call site's own import statement named exactly one of the three candidates. **This is a materially easier problem for Kotlin than it ever was for the TS pipeline** (which hit 56% of its index with wrong `symbol_name`s, and 25 real collisions on one field name alone) — Kotlin's per-file explicit-import convention gives a syntax-only resolver a real, deterministic disambiguation signal that TypeScript's own import/re-export model doesn't offer as cleanly.

## What this means concretely for Tasks 2–8

- **Task 2 (config shape)** and **Task 3 (`00-scan-repo.ts` port)** are now unblocked — proceed using tree-sitter-kotlin as the extraction library.
- **Task 4 (`01-extract-ast-evidence.ts` port)**: build the import-aware symbol table as part of this task, not as a separate later pass — it's load-bearing for any call-graph/RBAC fact from day one, per the finding above.
- **Confidence tagging**: per `07-...md`'s own recommendation, tag every call-graph/cross-module edge with a real confidence tier (`resolved_via_import`, `resolved_via_same_package`, `ambiguous`, `unresolved`) mirroring the TS pipeline's own `confirmed`/`probable`/`unresolved` model — never silently claim compiler-exact confidence for a heuristically-resolved edge.
- **Known, accepted limitation**: the call-then-navigation-chain assignment bug (and whatever causes the 2 still-unexplained files' errors) means a small, bounded set of real statements won't extract cleanly. Not blocking — same "honest, named limitation" treatment the TS pipeline already gives its own event-subscriber-extraction and Firestore-operation-detection gaps.
- **Revisit trigger for `kotlin-compiler-embeddable`**: if the real symbol table, once built against all 5 modules' real code, finds import-based resolution genuinely ambiguous or wrong at a materially higher rate than this bounded test (2 collisions in 136 files) suggested, escalate to Option 3 (hybrid) rather than accepting degraded confidence silently.
