# Priming Brief — Real, Current Practice on Agentic Tool-Call/Turn Budgets

**Purpose of this file:** hand this to a fresh Claude session as its first message (or tell it to read this file first). This project's own agent (`atomic-prd-agent.ts`, via Genkit's `ai.generate()`) is capped at `maxTurns: 25` — real tool-call iterations before Genkit force-aborts the run. Today, two real, independent test runs both hit that cap and aborted with zero output: one from a real, confirmed turn-budget-waste bug (the model held a confident, correct hit and didn't trust it, burning turns on query variants that couldn't work), the other from what looks like genuine breadth — a real three-repo business question that hadn't converged by turn 25. This raises a real, concrete question this project hasn't actually researched yet: **is a small, fixed turn cap like 25 the right shape at all for this class of task, and what do real, current production agentic systems actually use?** This is a research/report task — do not modify any file in this repository other than writing your own findings report (location at the bottom).
